## 0. 設計の考え方（先に）
- **初めての人が説明なしで使える**ことを一番にする。前案件では「使い方が分からない」が問題になった。
- 1画面でやることは1つ。**主なボタンは1画面に1つ**だけにする（下の表のとおり）。
- 読み取りは「仮版」で**まちがいが多い前提**。直す操作は「1回押すだけ」で終わるようにする。
- 待たせない：画像を選んだらすぐ保存し、読み取りは1枚ずつ進める。途中で画面を離れても続く。
- 指で押す部分はすべて **44ピクセル以上**。主なボタンは高さ52ピクセル。
- 決定済みの方針（Expo + React Native、Web版から、作り直しを減らす）と矛盾する点はない。

## 1. アプリ名（仮）と一文説明
- **アプリ名（仮）**：スクショ係
- **一文説明**：スクショを入れるだけで、クーポン・予定・お店などに分けて、期限が近いものを教えてくれる。
- 画面に出す短い説明：「スクショを入れると、種類ごとに分けて、期限をお知らせします」

## 2. 画面一覧と画面のつながり

| # | 画面 | やること（1つ） | 主なボタン |
|---|---|---|---|
| A | はじめて画面 | 何のアプリか知って、始める | 見本で試す |
| B | ホーム | 入れたスクショを見る | ＋ スクショを追加 |
| C | 読み取り画面 | 読み取りを待ち、結果を確かめる | できた |
| D | くわしく画面 | 1枚を確かめて直す | 使った／済んだ |
| E | 探す画面 | 言葉で探す | （なし。入力欄が主役） |
| F | メニュー画面 | データ・見本・説明の管理 | （なし） |

補助（画面ではなく、下からせり上がる小さな窓）
- 「仮版について」の窓
- 「消しますか？」の確認
- 「見本を消しますか？」の確認

### つながり
```
初回のみ
  A はじめて ──[見本で試す]────────────→ B ホーム（見本6件入り）
            └─[自分のスクショではじめる]→ 端末の画像選び → C 読み取り
                                          （選ばずにやめたら B ホーム・空）

B ホーム
  ├─[＋ スクショを追加] → 端末の画像選び → C 読み取り ─[できた]→ B
  ├─ カードを押す → D くわしく ─[使った／済んだ]→ B（「もとに戻す」付き）
  ├─ 探す欄を押す → E 探す ─ 結果を押す → D
  ├─ 「…」（右上）→ F メニュー
  └─ 「仮版」の印（左上）→ 仮版について の窓

D くわしく ─[このスクショを消す]→ 確認 → B
C 読み取り ─ 結果カードを押す → D（戻るとCへ）
```
- 戻る操作：どの画面も左上に「＜ もどる」（44ピクセル以上）。ブラウザの戻るでも同じ動きにする。
- 画像選びをやめた（何も選ばなかった）ときは、元の画面のまま（はじめて画面からのときだけホームへ）。

## 3. 各画面の中身

### A はじめて画面（初回だけ）
上から順に
1. アプリ名「スクショ係」と「仮版」の印
2. 大きめの文：「スクショを入れると、種類ごとに分けて、期限をお知らせします」
3. 3つの小さな説明（印＋一行。縦に並べる）
   - 「1．スクショを入れる」
   - 「2．クーポン・予定・お店などに分かれる」
   - 「3．期限が近いものが一番上に出る」
4. 注意（小さめの文字、灰色の枠）
   - 「今は試作の仮版です。読み取りはまちがいが多めです。あとで直せます。」
   - 「データはこのブラウザの中だけに入ります。ブラウザの記録を消すと、なくなります。」
5. **主なボタン**：「見本で試す」
6. 文字のボタン（下線つき、高さ44ピクセル以上）：「自分のスクショではじめる」

- 何枚も続くページめくりの案内は作らない。この1画面だけ。
- 「見本で試す」を押すと、見本6件を入れてホームへ。ホームの一番上に一言の案内を出す（Bを参照）。
- もう一度見たいときはメニューの「使い方をもう一度見る」から。

### B ホーム
上から順に
1. **上の帯**：左「スクショ係」＋「仮版」の印（押すと説明の窓）、右「…」（メニュー）
2. **一言の案内**（見本を入れた直後、1回だけ）
   - 「カードを押すと、種類や期限を直せます」［わかった］
3. **探す欄**（押すと探す画面へ）：「さがす（例：クーポン、カフェ）」
4. **期限が近いもの**（今日〜7日後で、済んでいないもの。無いときはこの枠ごと出さない）
   - 見出し：「期限が近いもの」
   - 近い順に最大3件。カードは横長で、左に種類の印、中央にタイトル、右に残りの日数
   - 残りの日数の言葉：クーポンなど「今日まで」「明日まで」「あと3日」／予定は「今日」「明日」「3日後」
   - 4件以上：「ほか2件を見る」（押すと全件をその場で開く）
5. **種類で分ける列**（横に流せる。押すと下の一覧がしぼられる）
   - 「すべて」「クーポン」「予定」「お店・場所」「買いたい物」「レシピ」「その他」。それぞれ件数つき（例：「クーポン 3」）
6. **一覧**（新しく入れた順。2列の小さな画像カード）
   - カード：画像（縮めたもの）、種類の印と名前、タイトル（2行まで）、期限があれば「10/31（金）まで」
   - 期限が過ぎたもの：灰色の文字で「期限切れ」
   - 読み取り中のもの：画像の上に「読み取り中…」と動く印
   - 見本：右上に「見本」の札
7. **済んだもの**（一覧の一番下、閉じた状態）：「済んだもの（3）」押すと開く。中のカードは薄く表示
8. 一番下の小さな文字：「データはこのブラウザの中だけにあります」
9. **主なボタン**（画面の下に固定、横いっぱい）：「＋ スクショを追加」

空のとき
- 1件もない：
  - 「まだスクショがありません」
  - 「クーポンや予定のスクショを入れると、種類ごとに分けます」
  - 主なボタン「＋ スクショを追加」はそのまま。その下に文字のボタン「見本で試す」
- 種類でしぼって0件：「クーポンはまだありません」

その他の表示
- 自分のスクショを初めて入れて、見本が残っているとき（1回だけ）：
  「見本を消しますか？」［消す］［のこす］（のこしても、あとでメニューから消せる）

### C 読み取り画面
画像を選ぶとすぐこの画面になる。選んだ画像は**その場で縮めて保存**し、読み取りは上から1枚ずつ行う。

上から順に
1. 上の帯：左「＜ もどる」、中央「読み取り」
2. 進み具合：「3枚中 1枚できた」と横長の進み具合の帯
3. 待ち時間の目安：「1枚 10秒ほどかかります。ほかの画面に行っても続きます」
   - 初めて読み取るときだけ：「はじめてだけ、準備に少し時間がかかります」
4. **1枚ずつのカード**（縦に並ぶ）
   - 待ち：画像＋「じゅんばんを待っています」
   - 読み取り中：画像＋「読み取り中…」と動く帯
   - できた：画像＋種類の印と名前＋タイトル＋期限（あれば）＋「ちがうときは押して直す」
     - 種類の印を押すと、6種類の選択がその場に出る（1回押せば決まる）
     - カードの他の部分を押すと D くわしく へ
   - 読めなかった：画像＋「文字が読めませんでした。種類は自分で選べます」（種類の選択を出す）
5. **主なボタン**（下に固定）：「できた」
   - 読み取りが残っていても押せる。押すとホームへ。残りはホームのカードで「読み取り中…」として続く

- 保存は自動。「保存する」ボタンは置かない（押し忘れで消えるのを防ぐ）。
- 一度に選べるのは20枚まで。超えたとき：「一度に入れられるのは20枚までです。はじめの20枚を入れました」

### D くわしく画面
上から順に
1. 上の帯：左「＜ もどる」
2. **画像**（画面の幅いっぱい。押すと大きく表示、もう一度押すと戻る）
3. **状態の札**（該当するときだけ）：「見本」「使った」「済んだ」「期限切れ」
4. **タイトル**：文字を押すとそのまま書き直せる。横に鉛筆の印
   - 空にしたとき：自動で「クーポン 10/19」の形に戻す
5. **種類**：見出し「種類」、6つの選び札を3つずつ2段で全部見せる。今の種類は色で塗りつぶし＋チェック
   - 押すとすぐ変わり、下に小さく「保存しました」
6. **期限**：見出しは種類で変える（クーポン＝「使える期限」、予定＝「日にち」、それ以外＝「期限」）
   - 読み取った日付の候補を札で並べる：「10/31（金）」「11/3（月）」
   - 続けて「日付を選ぶ」（端末の日付選びを開く）、「なし」
   - 今の期限は塗りつぶし＋その下に「あと12日」
   - 候補が無いとき：「日付は見つかりませんでした」＋「日付を選ぶ」「なし」
7. **読み取った文字**（閉じた状態）：「読み取った文字を見る」押すと開く。一行添える：「仮版なので、まちがいがあります」
8. **消す**（読み取った文字の下、赤い文字のボタン）：「このスクショを消す」
   - 確認の窓：「消しますか？ もとに戻せません。写真アプリの元の画像は消えません」［消す］［やめる］
9. **主なボタン**（画面の下に固定）
   - クーポン：「使った」
   - それ以外：「済んだ」
   - すでに使った・済んだもの：「まだにもどす」
   - 押すとホームへ戻り、下に「使ったにしました［もとに戻す］」を5秒出す

- 変更はすべて押した瞬間に保存。「保存」ボタンは置かない。
- 読み取り中のものを開いたとき：画像と「読み取り中です。終わると種類と期限が出ます」。種類・期限は先に選んでもよい（選んだものは読み取り後も上書きしない）。

### E 探す画面
上から順に
1. 上の帯：左「＜ もどる」
2. **探す欄**（開いたらすぐ文字を打てる状態）：「さがす（例：クーポン、カフェ）」右に「×」で消す
3. 何も打っていないとき：「種類から探す」として6種類の札（押すとその種類のものを下に出す）
4. **結果**：「5件見つかりました」＋ホームと同じカード。済んだものは下にまとめて薄く表示
   - 見つかった文字の部分をタイトルの下に一行で見せる（例：「…駅前の**カフェ** ことり…」）

空のとき
- 「『カフェ』は見つかりませんでした」
- 「ちがう言葉や、種類の名前（クーポン、予定など）でも探せます」

- 打つたびに結果が変わる（「探す」ボタンを押さなくてよい）。
- 探す対象：読み取った文字、タイトル、種類の名前。
- ひらがなとカタカナ、全角と半角、大文字と小文字の違いは同じとみなす（「くーぽん」でもクーポンが出る）。

### F メニュー画面
上から順に（すべて横長の押せる行、高さ52ピクセル）
1. 「仮版について」→ 説明の窓
2. 「使い方をもう一度見る」→ A はじめて画面
3. 見本の行（状態で変わる）
   - 見本があるとき：「見本を消す」
   - 無いとき：「見本をもう一度入れる」
4. 「データについて」の枠（押せない説明）
   - 「データはこのブラウザの中だけにあります」
   - 「ブラウザの記録を消す・別のブラウザで開く・長く使わないと、なくなることがあります」
   - 「今の量：スクショ 24枚」
5. 「すべて消す」（赤い文字）→ 確認の窓「すべて消しますか？ もとに戻せません」［すべて消す］［やめる］

### 補助：仮版について の窓
- 「今は試作の仮版です」
- 「文字の読み取りは簡単なしくみなので、まちがいが多めです。種類や期限は押すだけで直せます」
- 「本物のAIを使ったときの正確さは、この試作では確かめられません」
- 「お知らせ（通知）はスマホ版でつきます。今はホームの一番上に、期限が近いものを出します」
- ［とじる］

## 4. 読み取り中・失敗時の見せ方

### 読み取り中
- 選んだ直後に画像を保存し、カードを出す（「待たされて何も起きない」時間を作らない）。
- 1枚ずつ順番に読む。状態は3つの言葉だけ：「じゅんばんを待っています」「読み取り中…」「できた」。
- 全体の進み具合「3枚中 1枚できた」を常に見せる。
- 目安「1枚 10秒ほど」を出す。残り時間の数字は出さない（ずれると不信につながるため）。
- 初回は文字読み取りの準備（辞書の読み込み）がある：「はじめてだけ、準備に少し時間がかかります」。
- ほかの画面へ移っても読み取りは続き、ホームのカードに「読み取り中…」と出る。終わるとカードが自然に変わる。
- 全部終わったとき、ホームにいれば下に一言「3枚の読み取りが終わりました」（3秒）。

### 失敗したとき

| どんなとき | 見せ方 | その後 |
|---|---|---|
| 文字が見つからない | 「文字が読めませんでした。種類は自分で選べます」 | 「その他」で保存。タイトルは「スクショ 10/19」 |
| 画像が開けない（壊れている・形式が違う） | 「この画像は開けませんでした」 | 保存しない。ほかの画像は続ける |
| 読み取りが途中で止まった（画面を閉じた等） | カードに「読み取りが止まりました」［もう一度読む］ | 次に開いたときも残っている |
| 保存する場所がいっぱい | 「いっぱいで入りません。いらないスクショを消してください」 | 入らなかった枚数を伝える：「2枚入りませんでした」 |
| 読み取りのしくみ自体が動かない（古いブラウザ等） | 「このブラウザでは文字を読めません。種類と期限は自分で選べます」 | 画像は保存し、すべて「その他」で入れる |

- 失敗の文は「何が起きたか」＋「次にできること」の2つだけ。専門的な理由（エラーの番号など）は出さない。
- 赤い色で大きく警告しない。灰色の枠＋文字で落ち着いて伝える。

## 5. 見本データ
「見本で試す」で6件入れる。すべてタイトルの頭に【見本】を付け、カードに「見本」の札を出す。
画像は開発係が用意する「スクショ風の画像」（文字入りの簡単な画像）。読み取りはせず、結果を最初から入れておく（すぐ試せるように）。
日付は**入れた日から数える**（いつ試しても「期限が近いもの」に出るように）。

| 種類 | タイトル | 画像の中の文字（例） | 期限 | ねらい |
|---|---|---|---|---|
| クーポン | 【見本】カフェ ことり 100円引き | 「カフェ ことり／ドリンク100円引きクーポン／有効期限 ○/○まで」 | 2日後 | 「期限が近いもの」に出る。「使った」を試せる |
| 予定 | 【見本】ライブ ひかりホール | 「ひかりホール公演／○月○日（土）開場17:00 開演18:00」 | 5日後（候補に12日後も） | 「期限が近いもの」に出る。期限の候補を選び直せる |
| お店・場所 | 【見本】パン屋 こむぎ堂 | 「こむぎ堂／営業時間 8:00〜18:00／定休日 水曜／みどり駅 徒歩3分」 | なし | 探す「パン」で出る |
| 買いたい物 | 【見本】白いスニーカー | 「キャンバススニーカー ホワイト／¥5,980（税込）／カートに入れる」 | なし | |
| レシピ | 【見本】10分 親子丼 | 「親子丼（1人分）／材料：鶏もも肉、卵、玉ねぎ／作り方」 | なし | |
| その他 | 【見本】ゴミ出しの日 | 「燃えるゴミ 月・木／資源ゴミ 第2水曜」 | なし | どの種類にも入らないものは「その他」になる例 |

- 見本の中身は架空の店名・場所のみ。実在の店名は使わない。

## 6. 色・見た目の方針

### 全体
- 背景：やわらかい白（#FAF8F5）。カード：白（#FFFFFF）＋薄い影
- 文字：濃い墨色（#2B2B2B）、補足は灰色（#6B6B6B）
- 主なボタン：深い藍色（#34418C）に白文字。画面の中でこの色の塗りつぶしは主なボタンだけにする（何を押せばいいか迷わないように）
- 文字の大きさ：本文16ピクセル、見出し20ピクセル、最小14ピクセル
- 角の丸み：カード12ピクセル、ボタン・札は丸め多め

### 種類ごとの印（色＋形＋名前の3つで見分ける。色だけに頼らない）

| 種類 | 色 | 薄い背景 | 形の印 |
|---|---|---|---|
| クーポン | 赤紫 #B83280 | #FBEAF3 | チケット |
| 予定 | 青 #2B6CB0 | #E8F0FA | カレンダー |
| お店・場所 | 緑 #2F855A | #E6F4EC | 地図のピン |
| 買いたい物 | 黄土 #8A5A0B | #FBF1DE | 買い物ぶくろ |
| レシピ | 橙 #C05621 | #FCEDE3 | おなべ |
| その他 | 灰 #5F6B7A | #EEF0F3 | 点3つ |

- 札は「薄い背景＋濃い色の文字と印」。くわしく画面で選ばれている札だけ「濃い色の塗りつぶし＋白文字＋チェック」。文字と背景の見やすさ（明るさの差）は 4.5：1 以上を開発係が確認する。
- 期限の表示：今日・明日は赤（#C53030）の文字、2〜7日は濃い文字、過ぎたものは灰色「期限切れ」。必ず言葉を添える。
- 「仮版」の印：灰色の枠線だけの小さな札（目立ちすぎず、必ず見える）。
- 「見本」の札：点線の枠の小さな札。
- 動き：読み取り中の帯がゆっくり動く程度。大きな動きは使わない。

## 7. 開発係向けメモ

### 画面の場所（Expo Router の例）
- `src/app/index.tsx`（ホーム）、`welcome.tsx`（はじめて）、`import.tsx`（読み取り）、`item/[id].tsx`（くわしく）、`search.tsx`（探す）、`menu.tsx`（メニュー）
- 初回かどうかは設定の `seenWelcome` で判断し、未表示なら `welcome` へ。

### データの形

**Item（スクショ1枚）**
| 項目名 | 型 | 内容 |
|---|---|---|
| id | string | 一意の番号 |
| createdAt | string（日時） | 入れた日時 |
| updatedAt | string（日時） | 最後に変えた日時 |

### 種類を決めるルール（仮版）

### 期限の候補を出すルール（仮版）
- 読む形：「2026/10/31」「2026年10月31日」「10/31」「10月31日」「10月31日(金)」
- 年が無いとき：今年とみなす。その日がすでに30日以上前なら来年とみなす。
- 候補は最大3つ。どれを期限にするか：
  - クーポン：「期限」「まで」に一番近い日付。無ければ一番遅い日付
  - 予定：今日以降で一番早い日付
  - それ以外の種類：候補は出すが、自動では期限にしない（`dueDate` は null）
- 人が種類を付け替えたとき：期限を人が直していなければ、新しい種類のルールで期限を選び直す。
- タイトル：読み取った文字の最初の5行のうち、4文字以上で一番長い行（20文字で切る）。無ければ「種類名 月/日」。
