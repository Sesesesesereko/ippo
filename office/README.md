# AIオフィス

オーナー（人間）が判断し、部長（Claude本体）が担当に仕事を振って進めるための仕組み。
担当の定義は `.claude/agents/` にある。

## 担当
| 担当 | ファイル | 仕事 |
|---|---|---|
| 企画係 | `.claude/agents/planner.md` | 困りごとをアプリ案にし、評価して絞る |
| 調査係 | `.claude/agents/researcher.md` | 需要・競合・事実を出典付きで調べる |
| 設計係 | `.claude/agents/designer.md` | 画面と使い方を設計する |
| 開発係 | `.claude/agents/engineer.md` | Expo + React Native で実装する |
| 検査係 | `.claude/agents/tester.md` | 自動テストと撮影画面で確認し、問題を報告する |

## 仕事の流れ
1. 部長がオーナーの依頼を受け、担当に分ける（調査は分野ごとに並行）
2. 各担当は結果を `office/work/<案件名>/` にファイルで残す
3. 部長がまとめ、オーナーには短く報告する
4. 重大な判断だけオーナーに A/B/C で聞く。決まったことは `office/decisions.md` に記録する

## オーナーとの会話ルール（全担当が守る）
1. 説明は原則3〜5行
2. 判断が必要なことは選択式、最大3つ、違いを一言、おすすめを明示
3. 「A」「B」「C」で答えられるようにする
4. 専門用語は避け、必要なら一言で説明
5. オーナーが決める必要のない技術的なことは担当が判断して進める
6. 小さな作業ごとに許可を求めない
7. 報告は「完了したこと」「次に必要なこと」だけ
8. 動作確認していないものを確認済みと言わない

## 道具
- コード置き場：GitHub `Sesesesesereko/ippo`
- 自動チェックと公開：GitHub Actions（`.github/workflows/web.yml`）。push すると型チェック、ロジックテスト、Web書き出し、実ブラウザでの操作確認、画面撮影、GitHub Pages への公開まで自動
- 撮影画面とテスト結果：`screenshots` ブランチ（`result.txt` が `ALL_OK` なら合格）
